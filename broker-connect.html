CONTROL PATH

The intended production path from user account to live broker execution.
01SELECT BROKER

Choose the broker whose documented API matches the user's account and instrument set.

02AUTHORIZE AT BROKER

Open the broker's own domain. The user signs in there and creates/approves an API credential.

03VERIFY CREDENTIAL

KINGBOT sends the credential to the authenticated backend gateway over HTTPS for account validation.

04CONNECT ACCOUNT

The gateway creates a per-user broker session and starts balance, positions, orders and execution monitoring.

05ENABLE BOT

Only a verified connected broker account can be selected as the execution account for a KINGBOT strategy.

06LIVE MONITORING

Trade events, P/L, margin, position state and broker errors stream back to the user's terminal.

EXECUTION SAFETY

Browser code must never permanently store broker secrets. The production gateway should verify the Firebase ID token, encrypt credentials at rest, enforce per-user authorization, apply broker-specific scopes, and keep an auditable order/event trail.

SUPPORTED CONNECTIVITY MODEL

For web-based brokers, use OAuth where available. For token-based APIs, the user creates the credential on the official broker domain and pastes only the required API credential. KINGBOT then validates the credential server-side. Real trading is enabled only after the broker adapter confirms authorization and the execution engine is explicitly armed.
